Flight Booking Website — Explanation (Part 4/5)

Part 4: Frontend structure, shared JS, and page behaviors.

1) Frontend architecture

The frontend is a collection of HTML pages under frontend/. They share styling via frontend/css/style.css and JavaScript via frontend/js/*.js.

  • Navigation is by full page loads (no SPA router).
  • State is stored in browser storage (usually localStorage).
  • Backend is called via fetch() returning JSON.

2) Styling: frontend/css/style.css

This is the central stylesheet. It defines:

  • Layout (headers/nav, containers, cards)
  • Form styling (inputs, buttons, validation messages)
  • Tables and dashboard styles
  • Responsive rules for smaller screens

3) Shared API wrapper: frontend/js/api.js

This file centralizes how the browser talks to the backend. It commonly provides:

  • Base URL: a string for the backend API root.
  • request helper: sets headers, serializes JSON, parses JSON response.
  • Modules: AuthAPI, FlightsAPI, BookingsAPI, AirportsAPI, etc.

Important mismatch: parts of this wrapper target “World B” endpoints (airports/airlines/seat classes). Some of the dashboard pages target “World A” endpoints (company/passenger schema).

4) Main UI logic: frontend/js/main.js

This file typically attaches event listeners to forms/buttons and implements page behaviors. Examples of common logic:

  • Handle search form submit (redirect to results page with query params).
  • Load dynamic lists like cities/airports (calling backend endpoints).
  • Read current user from localStorage to personalize UI.

5) Core pages

PagePurpose
index.htmlLanding page + entry point to search / login.
login.htmlLogin form; on success stores user info and redirects by user type.
register.htmlRegister form; chooses passenger vs company and posts to register endpoint.

6) Passenger pages (World A)

passenger-dashboard.htmlShows passenger bookings list and actions.
passenger-profile.htmlShows/edit passenger profile; upload photo/passport; change password.
search-results.htmlShows flights found from a search; usually calls search endpoint.
flight-info.htmlDisplays one flight details and booking actions.

7) Company pages (World A)

PageWhat it does
company-dashboard.htmlLists company flights and links to details.
add-flight.htmlCreate a flight + define itinerary (cities sequence).
flight-details.htmlFlight details for company; lists pending/registered passengers.
company-profile.htmlUpdate company profile data (bio/logo/etc.).

8) Messaging pages

Passenger and company both have pages to view conversations and send messages. Those pages call backend/api/messages.php.

  • frontend/js/main.js
  • All HTML pages under frontend/ (login/register, passenger/company dashboards, flight/search pages, profiles, messaging).
